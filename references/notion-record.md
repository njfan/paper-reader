# Notion 论文阅读记录

仅在需要保存、查重或配置 Notion 时读取本文件。

## 配置状态

- 本地配置文件：`references/notion-config.md`，不得提交到公开仓库。
- 示例文件：`references/notion-config.example.md`。
- 配置存在时，从中读取数据库 URL、数据源 ID 和可选视图 ID；每次写入前仍须 fetch 当前数据库，以实际 schema 为准。
- 配置缺失时，正常阅读；不要在阅读流程中主动询问配置。安装完成时由执行安装的助手询问是否立即配置；之后仅在用户明确要求配置或变更时执行本文件的首次创建流程。
- Notion 工具未连接或无写权限时，说明需要连接或授权 Notion；保留已经输出的论文笔记。

## 首次创建模板

用户同意配置后：

1. 检查 Notion 工具和写入权限。若必须指定父页面且当前上下文无法确定目标位置，只询问用户希望放在哪个页面。
2. 搜索目标位置是否已有适用的 `paper-reader` 数据库，避免重复创建；发现候选时先核对字段。
3. 没有可复用数据库时，创建名为 `paper-reader` 的数据库。每行代表一篇论文，使用以下属性：
   - `论文标题`：Title
   - `论文链接`：URL
   - `作者`：Text
   - `年份`：Number
   - `中稿期刊/会议`：Text
   - `领域`：Text
   - `输入`：Text
   - `输出`：Text
   - `一句话概括`：Text
   - `直接 Baseline`：Text
   - `灵感来源`：Text
   - `核心问题`：Text
   - `创新点`：Text
   - `实验结论`：Text
   - `阅读日期`：Date
4. 若工具支持，创建或保留一个便于快速浏览全部记录的表格视图；不因视图创建能力缺失而宣称配置失败。
5. 将返回的数据库 URL、数据源 ID 和可用的视图 ID 写入本地 `references/notion-config.md`，格式与示例文件一致。不要把配置内容写进 `SKILL.md` 或公开文件。
6. 配置完成后，继续处理用户原本的论文阅读请求；除非用户明确表示只配置不保存，否则将刚完成的论文笔记保存为第一条记录，并返回数据库链接。

## 字段与页面正文

用实际 fetch 到的 schema 写入属性。`中稿期刊/会议`只填写有来源确认的正式录用或发表场所；未确认时留空。长列表在属性中压缩为一行，完整分析放在页面正文。

正文沿用 skill 的九个标题及顺序。基本信息包含标题、作者、组织机构、年份、中稿期刊/会议、论文链接、领域、输入、输出，不加入 Notion 记录链接。组织机构只写在正文，除非数据库实际已有对应字段，不新增属性。

写入前读取 `notion://docs/enhanced-markdown-spec`，将消融表转为 Notion 支持的 `<table>`。页标题只放在 `论文标题` 属性。Baseline 与相关论文的链接保留在正文；`直接 Baseline` 和 `灵感来源` 属性只存方法名。实验、消融与局限只标章节、表号或图号，不重复链接论文首页。

## 已配置时的每次保存

1. 在阅读论文前读取配置并 fetch 数据库。以 DOI 或 arXiv ID 为优先标识，必要时辅以标题和年份查重；同篇论文的 PDF、摘要和 HTML 地址视为一篇。
2. 无匹配时正常阅读，完成后创建一行，填写可确认属性、当地阅读日期和完整九段笔记。
3. 有匹配时 fetch 对应页面，然后询问用户是否重新阅读并覆盖。明确说明覆盖会替换原页面全部笔记正文；用户拒绝时停止阅读，只返回现有记录链接。
4. 用户确认后重新阅读，用本次九段笔记整体替换正文，更新可确认属性和阅读日期；保留原行，不创建重复记录。
5. 创建或更新结果不确定时先查询确认，再决定是否重试。保存成功后可在九段笔记之后简短说明；失败时如实报告并保留阅读结果。

用户明确要求本次不保存时，跳过本流程。不要批量回填旧论文。
